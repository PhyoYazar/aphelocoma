# T14 — Cover the last board warning branch and correct the record

## Goal

A pre-release audit requested by the advisor found one real coverage gap and one false claim. Close
both. The gap is the `unreadable_status_report` branch, flagged inline in DOC-040 since T10 and
deferred twice. The false claim is the assertion file's statement that the branch is untested, which
stops being true the moment the test lands.

## Scope

1. **The untested branch.** `_validate_status_report` in `src/aphelocoma/hamilton_state.py` has six
   warning branches. Five have dedicated tests; `unreadable_status_report` has none. Add one, reaching
   the branch through invalid UTF-8 rather than a permissions change, so it behaves the same for every
   user and on every filesystem CI runs on — a chmod-based test passes as an ordinary user and fails
   as root.
2. **DOC-040's coverage-gap paragraph.** It states the branch is "not exercised by any current test"
   and "flagged as a coverage gap, not asserted as tested here". Both become false with the test in
   place. Replace them with the citation, and state the branch total the file can actually back.

## Non-scope

- Any behavior change. `_validate_status_report` is correct; only its test coverage was short.
- The duplicated `phase` field. The audit initially called it a product defect; it is not — PROTOCOL §2
  has required writing both files since T2, and the validator enforces it. Recorded at ledger seq 295.
- Redeployment. This touches `tests/` and `docs/` only; the deployed bundle is `references/`.
- Version bump, tag, merge, or push. The CHANGELOG's `[0.3.0] — Unreleased` marker stays as it is.

## Interfaces / files touched

- `tests/test_hamilton_state.py`
- `docs/documentation-assertions-v0.3.md`

## Acceptance criteria

- [ ] A test asserts the `unreadable_status_report` code specifically, and that the report still passes
  (a warning, never an error).
- [ ] The test reaches the branch without `chmod`, so it is not user- or filesystem-dependent.
- [ ] DOC-040 no longer claims the branch is untested, and cites the new test by its full id.
- [ ] Any branch-count claim in DOC-040 matches the number of `issues.warning` calls actually in
  `_validate_status_report` — counted, not assumed.
- [ ] Every backticked test ID in the assertions file still resolves under unittest discovery.
- [ ] The full suite and `aph doctor` pass.
