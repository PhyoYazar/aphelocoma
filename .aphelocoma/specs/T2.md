# T2 — Version and harden Hamilton project state

## Goal

Make Hamilton state explicitly versioned, privacy-aware, migratable, and mechanically validated while
preserving the Codex dispatch semantics from baseline commit `79697c0`.

## Scope

- Schema/protocol version fields across templates, examples, start/resume/status instructions.
- Backed-up check/apply migration for unversioned v0.2 state with rollback on failure.
- `tracked`/`local` visibility and transient dispatch policy.
- Stronger validator invariants: reviewer independence, event ordering/references, IDs/transitions,
  transient tracked content, and representative secret material.
- Final Codex result schemas and dispatch/protocol contract.
- Project-state doctor checks callable through the T1 check registry.

## Non-scope

- Installing generated roles or manipulating host-tool configuration (T3).
- Removing unrelated legacy skills/adapters (T4).

## Acceptance criteria

- [ ] Tests are written first for unversioned/current/future state, failed migration rollback,
  reviewer=builder, out-of-order reviews, missing references, invalid transitions, tracked dispatch
  content, and representative secrets.
- [ ] Current and migrated project state validates; unsupported future versions fail with remediation.
- [ ] Migration creates a recoverable backup, validates the migrated result, and restores the original
  byte-for-byte when an injected failure occurs.
- [ ] A task cannot pass validation unless its critique actor is independent from its builder and the
  critique/review events occur in valid order.
- [ ] Durable state never contains dispatch prompts/results/logs; privacy visibility is explicit.
- [ ] Baseline Codex exec/collab selection, role labeling, schema enforcement, sandboxing, and
  model/effort behavior remain represented consistently across protocol, schemas, and tests.
- [ ] T1's doctor registry gains project-state checks without changing T1-owned CLI/path files.
