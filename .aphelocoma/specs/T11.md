# T11 — Reduce the board to stage and tasks, and keep it in a file

## Goal

The advisor wants one thing from the board: what stage the project is at, which tasks are done, and
which are left. Nothing else. And they want it in a file they can open any time, not only in a
terminal that has already scrolled away.

## Scope

- Narrow the human-readable `aph status` output to the stage and the task list.
- Write the same content to `.aphelocoma/STATUS.md`, regenerated whole on every write.
- A staleness stamp on that file, and a validator warning when it falls behind the ledger.
- Update `PROTOCOL.md` §5.6 from "print" to "print and write", with the narrowed content.

## Non-scope

- The four trigger points, which stand as written in §5.6.
- `--json`, which stays complete. It is machine-facing, the fields already exist, and removing them
  buys the advisor nothing.
- Schema, protocol version, or migration changes. `STATUS.md` is a derived view, not new durable
  state — no `state.schema.json` entry, and `tasks.json` remains the single source of truth (§5).
- Version bump, tag, push, or release.

## Interfaces / files touched

- `src/aphelocoma/cli.py` — narrow `render_status_board()`; add the `--write` path.
- `src/aphelocoma/hamilton_state.py` — the `STATUS.md` renderer and the staleness check.
- `skills/aph-hamilton/references/validate.py` — surface the staleness warning (shim only if needed).
- `skills/aph-hamilton/references/PROTOCOL.md` — §5.6 content and the write rule.
- `skills/aph-hamilton/skill.md`, `README.md`, `CHANGELOG.md`
- `tests/test_cli.py`, `tests/test_hamilton_state.py`
- `.aphelocoma/ledger/agents/fullstack-developer#1.md`

## Acceptance criteria

- [ ] Failing tests are written first for every behavior below.
- [ ] `aph status` human output shows exactly: the project name, the current stage (`phase`), a
  done/total count, and one line per task with its id, status as a word, and title. The repo/git line,
  the separate blocked section, the next-actionable line, and the schema/protocol/visibility line are
  removed from human output.
- [ ] A task that is `blocked` still reads as blocked in its own row — the status word carries it, so
  nothing is hidden by removing the separate section.
- [ ] `aph status --write [path]` regenerates `.aphelocoma/STATUS.md` from `tasks.json` and
  `hamilton.json`, overwriting it whole. It is never appended to and never incrementally patched, so it
  cannot accumulate drift.
- [ ] `STATUS.md` carries a generated stamp naming the UTC time and the ledger `seq` it was generated
  from, so a reader can tell whether it is current.
- [ ] `STATUS.md` is written atomically (temporary file + replace, per `conventions.md`) and is
  committed with the project — it must not be git-ignored.
- [ ] Without `--write`, the command still writes nothing anywhere. A test asserts `.aphelocoma/` is
  byte-identical after a plain `aph status` run, `STATUS.md` included.
- [ ] The validator reports a **warning**, never an error, when `STATUS.md` is missing or its stamped
  `seq` is behind the ledger's last `seq`. A stale board never blocks `resume`; the warning names how
  far behind it is and that `aph status --write` refreshes it.
- [ ] `--json` output is unchanged, including the repo fields.
- [ ] `PROTOCOL.md` §5.6 states the narrowed content and that the orchestrator both prints and writes
  the board at the four existing trigger points, and that `tasks.json` stays authoritative when the two
  disagree.
- [ ] `README.md` and `CHANGELOG.md` describe `--write` and `STATUS.md` under the unreleased 0.3.0
  entry; `skill.md` stays accurate.
- [ ] The full standard-library suite, the Hamilton validator, and `aph doctor` all pass before handoff.
- [ ] A real `aph status --write .` on this project produces a `STATUS.md` whose task list matches
  `tasks.json` exactly.

## Context for the implementer

T9 shipped a richer board — git branch, HEAD, commit count, tree cleanliness, a blocked section, a
next-actionable line. The advisor has since narrowed what they want to see. This is a deliberate
reduction of reviewed work, not a defect in it: keep the underlying data in `--json`, and take it out
of the human view.
