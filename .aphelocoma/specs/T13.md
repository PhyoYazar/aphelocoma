# T13 — Close the residual documentation inconsistencies

## Goal

The T10 review passed but found seven places where the board documentation is still imprecise or
incomplete. None blocks the feature — the code is correct and `PROTOCOL.md` §5.6 and `skill.md` agree
— but each is a place where a reader following one document alone gets it slightly wrong.

## Scope

1. **`PROTOCOL.md` §2 Phase 5 asymmetry.** The pass branch names the board; the fail branch does not,
   although §5.6 trigger 3 requires a board on `review_failed`. An orchestrator following Phase 5 alone
   refreshes on a pass and skips on a bounce-back.
2. **`PROTOCOL.md` §5.5 and `docs/documentation-assertions-v0.3.md` DOC-037.** "No ledger event records
   the commit SHA" is false: ten historical `task_completed` notes name one, as does a post-commit
   advisor `decision`. Narrow it to what is actually true — no event a task needs *before* its own
   commit can carry that commit's SHA.
3. **`PROTOCOL.md` §5.5 characterization.** It calls `task_completed` one of "every event a task needs
   to reach `done`", but `hamilton_state.py` raises `invalid_transition` unless the task is already
   `done`, so it follows `done` rather than producing it. Only `critique` and `review_passed` gate it.
4. **`PROTOCOL.md` §5.6 bolded paragraph.** It still carries only the commit-relative half of the
   ordering, sitting beside the precise form in trigger 1. A reader anchoring on the bold imperative
   can still regenerate before appending `task_completed`.
5. **`README.md` directory tree.** It lists `.aphelocoma/`'s contents with no ellipsis, so it reads as
   exhaustive, but omits `STATUS.md` — which the same README documents as committed with the project.
6. **`references/roles/*.md` (13 files).** Each lists `task_completed` in the builder's own ledger
   rule, but a builder logging it would produce an `invalid_transition`; all eleven real ones were
   logged by the orchestrator. Correct the rule in each.
7. **`references/ABOUT.md`.** Never mentions `aph status`, the board, or `STATUS.md`, and its
   `.aphelocoma/` tree omits the file the same way the README's does.

## Non-scope

- Any behavior change. Words match code, never the reverse.
- The four trigger points, the narrowed board content, and the warn-not-error decision.
- Version bump, tag, push, or release.
