# T9 — Show a progress board at every milestone

## Goal

Give the advisor consistent visibility into a Hamilton run without asking for it: a single board that
shows which tasks are done, which are left, and the state of the working repo — printed automatically
when a task completes, when work is blocked or bounced back, and at every `resume`.

## Scope

- A read-only `aph status [path]` command that renders the board from `.aphelocoma/` plus Git.
- Human-readable output and a stable `--json` form, matching the `aph doctor` convention.
- Protocol text that defines the board's content and the moments it must appear, with
  orchestrator-rendered output as the documented fallback when `aph status` is unavailable.
- Tests, changelog, and user-facing documentation for both.

## Non-scope

- Writing any board file into `.aphelocoma/` — the board is printed, never persisted. `tasks.json`
  stays the single source of truth (§5) and no derived state is added to the tracked project.
- Appending ledger events for rendering a board. Looking is not an action.
- New schema, protocol, or migration semantics; no `schema_version` or `protocol_version` change.
- Test-run or CI status per task — Hamilton records no such state today; adding it is separate work.
- Version bump, tag, push, or release. 0.3.0 is still unreleased; the advisor owns publishing.
- Reviving the removed `aph-status` skill. That name is legacy-cleanup surface (`legacy.py`,
  `tests/test_package_inventory.py`); the board is a CLI command. The empty leftover directory
  `skills/aph-status/` is untracked and gets removed as housekeeping.

## Interfaces / files touched

- `src/aphelocoma/hamilton_state.py` — a `summarize_project()` API returning the board's data, reusing
  the existing state loaders and Git helpers.
- `src/aphelocoma/cli.py` — the `status` subcommand, `COMMANDS`, help topic, and rendering.
- `skills/aph-hamilton/references/PROTOCOL.md` — board content + trigger points + fallback.
- `skills/aph-hamilton/skill.md` — the `status` and `resume` modes point at `aph status`.
- `tests/test_cli.py`, `tests/test_hamilton_state.py` — subprocess and unit coverage.
- `README.md`, `CHANGELOG.md` — the command and its behavior.
- `.aphelocoma/ledger/agents/fullstack-developer#1.md`

Prefer extending `hamilton_state.py` over adding a runtime module: `RELEASE_RUNTIME_FILES` is
duplicated in `lifecycle.py`, `references/validate.py`, and `references/migrate.py`, and a new file
must be added to all three or runtime discovery drifts.

## Acceptance criteria

- [ ] A failing test is written first: `aph status` on a fixture Hamilton project asserts the board's
  contents before any implementation exists.
- [ ] The board reports, for the project at the given path (default `.`): project name, phase,
  schema/protocol version, `tracked`/`local` visibility, a done/total progress count, one line per
  task carrying its id, status, title, and owner, any blocked tasks called out, and the next
  actionable task with its owner.
- [ ] The board reports the repo situation: current branch, short HEAD, the number of commits made
  since the Hamilton run began, and whether the working tree is clean or has uncommitted files.
- [ ] `--json` emits stable machine-readable output covering the same fields, following the shape and
  conventions already used by `aph doctor --json`.
- [ ] Accessibility holds per `conventions.md`: no colour when `NO_COLOR` is set or stdout is not a
  terminal, and the board stays understandable without colour or symbols — every task line carries its
  status as a word, never a glyph alone.
- [ ] Exit codes follow `conventions.md`: `0` on success, `1` with actionable remediation when the
  path has no `.aphelocoma/` or its version is unsupported, `2` for unexpected internal failure. No
  Python traceback reaches the user.
- [ ] A non-Git project, a detached HEAD, and a project whose Git worktree is unreadable each render a
  board with the repo line degraded to a plain statement — never a crash and never a wrong claim.
- [ ] The command is provably read-only: a test asserts every file under `.aphelocoma/` is byte-identical
  after the command runs, including `events.jsonl`.
- [ ] `PROTOCOL.md` states the board's required content, the four moments it must appear (after each
  `task_completed` commit, on `blocked`, on `review_failed`, and at the top of every `resume`), and
  that the orchestrator renders the same board itself when `aph status` is missing or older than the
  protocol — so a version skew degrades output instead of breaking the run.
- [ ] `skill.md`'s `status` and `resume` modes reference `aph status` as the fast path and keep the
  existing crew table and validator verdict.
- [ ] Documentation claims match tested behavior: `README.md` lists the command and `CHANGELOG.md`
  records it under the unreleased 0.3.0 entry.
- [ ] The full standard-library suite, the Hamilton validator against this project, and `aph doctor`
  all pass before handoff.
