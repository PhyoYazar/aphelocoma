# T5 — Reposition and document Aphelocoma

## Goal

Make public documentation accurately present Aphelocoma as the portable Hamilton agent crew and
explain the v0.3 breaking transition, safety model, support matrix, and recovery behavior.

## Scope

- Rewrite README and CLI examples.
- Add changelog/migration notes.
- Document Claude/Codex tested/minimum versions, parallel capability detection, sequential fallback,
  privacy visibility, legacy default/custom data, backups, rollback, and command behavior.
- Remove outdated “no dependencies,” “never shared,” context-layer, Cursor, and automatic-sync claims.

## Non-scope

- Runtime behavior or implementation changes.
- Publishing/tagging the release.

## Interfaces / files touched

- `README.md`
- `CHANGELOG.md`
- `docs/migration-v0.3.md`
- `docs/documentation-assertions-v0.3.md`
- User-facing prose in `skills/aph-hamilton/references/ABOUT.md`

## Acceptance criteria

- [ ] A documentation assertion checklist is written first and maps every behavioral claim to an
  automated test or explicit support-policy statement.
- [ ] The opening explains Aphelocoma/Hamilton in one sentence and the first-run flow in three steps.
- [ ] Migration notes state that v0.3 is breaking and that neither default nor custom legacy data is
  read, modified, or deleted.
- [ ] Deploy/undeploy/update/uninstall recovery and ownership behavior match T3 tests exactly.
- [ ] Privacy documentation distinguishes durable tracked/local state from transient dispatch data.
- [ ] Claude/Codex are the only first-class targets; minimum/tested versions and sequential fallback
  are explicit.
- [ ] No removed second-brain feature or unsupported portability claim remains.
