# T7 — Make deployed state tools locate the installed runtime

## Goal

Make the directly invoked Hamilton `validate.py` and `migrate.py` commands work from deployed Claude
Code and Codex skill copies without requiring callers to set `PYTHONPATH`.

## Scope

- Runtime discovery for source-checkout, default installed-root, and custom `APHELOCOMA_ROOT` layouts.
- Actionable, traceback-free failure when no compatible runtime can be found.
- Installed-and-deployed subprocess regressions for both state tools and both supported hosts.
- Local reinstall/redeploy verification after the reviewed fix.

## Non-scope

- Applying migration to the advisor's `cctv-event-intelligence` project.
- Changing Hamilton schema/protocol versions or migration semantics.
- Adding a new CLI command, host, dependency, tag, push, or release.

## Interfaces / files touched

- `skills/aph-hamilton/references/validate.py`
- `skills/aph-hamilton/references/migrate.py`
- `tests/test_release_smoke.py`
- `.aphelocoma/ledger/agents/fullstack-developer#2.md`

## Acceptance criteria

- [ ] A failing test first reproduces `ModuleNotFoundError: No module named 'aphelocoma'` by invoking
  both scripts from deployed Claude and Codex skill copies with no `PYTHONPATH`.
- [ ] Both deployed scripts locate the matching runtime under the default install root and a custom
  `APHELOCOMA_ROOT`, independent of the caller's current directory.
- [ ] Source-checkout invocation continues to work.
- [ ] A genuinely missing runtime fails with actionable installation/deployment remediation and no
  Python traceback.
- [ ] Migration remains read-only in `check` mode; no migration is applied to the advisor's external
  test project.
- [ ] The focused regression, full standard-library suite, Hamilton validator, Bash syntax, and
  patch checks pass.
- [ ] After independent CP4 approval, local v0.3 is reinstalled and both hosts are redeployed; direct
  deployed-script smoke tests pass before handoff.
