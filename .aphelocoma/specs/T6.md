# T6 — Add cross-platform CI and verify v0.3 readiness

## Goal

Prove the Hamilton-only reset works on supported operating systems and host tools, survives injected
failures, preserves protected data/configuration, and is ready for independent release review.

## Scope

- Ubuntu and macOS CI using the standard-library test suite.
- Cross-tool isolated smoke tests for Claude Code and Codex deployment/undeployment.
- Repeated-operation, failure-injection, fallback, migration, generator, validator, privacy, and
  package-inventory scenarios.
- Version bump/readiness report after all checks pass.

## Non-scope

- Publishing, pushing, or creating a GitHub release/tag.
- Adding new product features or platforms.

## Interfaces / files touched

- `.github/workflows/ci.yml`
- `tests/test_release_smoke.py`
- `tests/fixtures/release/**`
- `VERSION`
- `docs/release-readiness-v0.3.md`

## Acceptance criteria

- [ ] Release smoke tests are written before CI/release wiring and fail when either tool path, OS
  scenario, protected legacy path, or required Hamilton asset is omitted.
- [ ] CI runs the full suite on current supported Ubuntu and macOS runners.
- [ ] Claude and Codex clean deploy, repeated deploy, repeated undeploy, collision, and sequential
  fallback scenarios pass in isolated homes.
- [ ] Interrupted install/update rollback and ownership-aware uninstall tests pass without changing
  default/custom legacy data or unowned configuration.
- [ ] Hamilton migration, validator independence/order checks, transient/secret checks, Codex
  generation, and package inventory all pass.
- [ ] Independent CP4 review finds every T1–T6 acceptance criterion satisfied.
- [ ] `VERSION` becomes `0.3.0` only after the release-readiness report records all checks passing.
