# T10 — Make the board documentation true everywhere

## Goal

Three reviews found documentation that no longer matches what the code does. One of them is
operational, not cosmetic: `skill.md` still tells the orchestrator to write the board *after* the
commit, which is the exact ordering T12 reversed. An orchestrator reading it reproduces the defect
T12 fixed.

## Scope

1. **`skills/aph-hamilton/skill.md`** — the write-after-commit ordering, and any other board wording
   that predates T11/T12. This is the in-context instruction the orchestrator actually reads, so it
   must agree with `PROTOCOL.md` §5.6 exactly.
2. **`README.md`** — the staleness warning is described as firing only when `STATUS.md` is missing or
   behind. It now also fires when the stamp is ahead of the ledger, names no sequence, or cannot be
   read.
3. **`skills/aph-hamilton/references/PROTOCOL.md` §5.6, trigger 1** — tighten to say the board is
   regenerated *after* the `task_completed` event is appended and *before* the commit. Both readings
   are currently literal, and the looser one causes a spurious "1 event behind" warning on a freshly
   committed board.
4. **`PROTOCOL.md` §5.5 vs §5.6** — §5.5 says to record the commit SHA in the `review_passed` note,
   but §5.6 now requires the board to be regenerated before the commit, so no event written before the
   commit can carry its SHA. Resolve the contradiction: state that the git subject carries the task id
   and that this is the cross-reference, or name whichever convention you judge correct. It must not
   ask for something impossible.
5. **`docs/documentation-assertions-v0.3.md`** — DOC-002 asserts a CLI surface without `status` while
   citing the very test T9 changed as its proof; DOC-006's test-ID list is incomplete. Re-check every
   other assertion in that file against current behavior, not only these two.

## Non-scope

- Any behavior change. This task changes words to match code, never code to match words. If you find
  a case where the code is wrong and the docs are right, report it at handoff rather than fixing it.
- `CHANGELOG.md`, which T9 and T11 already updated correctly.
- Version bump, tag, push, or release.

## Acceptance criteria

- [ ] `skill.md`'s board wording matches `PROTOCOL.md` §5.6 on every point, the regenerate-before-commit
  ordering included. A reader following either one alone produces the same behavior.
- [ ] `README.md` describes every condition that raises the staleness warning, and describes it as a
  warning that never blocks a resume.
- [ ] §5.6 trigger 1 names the ordering unambiguously: after the `task_completed` event is appended,
  before the commit.
- [ ] §5.5 and §5.6 no longer contradict each other about the commit SHA, and neither asks for
  something that cannot be done.
- [ ] DOC-002's command list includes `status` and its cited proof matches what that test now asserts.
- [ ] DOC-006's test-ID list matches the tests that exist.
- [ ] Every other assertion in `docs/documentation-assertions-v0.3.md` is re-checked against current
  behavior; state in the handoff that the sweep happened and what it found.
- [ ] No assertion is marked proven on the strength of a check that does not prove it.
- [ ] The full standard-library suite, `aph doctor`, and the Hamilton validator still pass. Run the
  validator against the **repository bundle** (`APHELOCOMA_ROOT` pointed at a nonexistent directory),
  because the installed runtime predates this work and silently skips the new checks.
